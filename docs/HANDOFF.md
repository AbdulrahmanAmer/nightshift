# Nightshift — orchestrator handoff (position file)

Read this first in a fresh session. It says where the project stands, what is decided, what is in flight, and what to do next. Update it whenever the position changes.

## What we are building
A Windows installer package (`Nightshift-<ver>.zip` with `INSTALL.cmd`) that turns one RTX 16 GB PC into an offline AI studio: writes original stories, narrates them (Qwen3-TTS GGUF via qwentts.cpp), renders 10–20 min long-form videos plus Shorts, cuts clips from the owner's own videos, with a local web dashboard and an Assistant on the local Qwen model. Spec: `BUILD_SPEC.md` (v2). Process: `docs/ENGINEERING.md`. Plans: `docs/superpowers/plans/`.

## Non-negotiables (from the owner)
- Nothing heavy runs on the authoring laptop: no models, torch, llama.cpp, whisper, no Python venv for the product. Tests run in GitHub Actions (public repo, windows-latest). Builders write, commit, push, read CI.
- Never spawn agents on the Fable model; builders are Sonnet 5.5 at effort high; Opus only for design/architecture. Fable orchestrates, reviews, merges, keeps contracts.
- The partner's GPU PC is reached only through the shipped bundle (Google Drive). The codebase stays there for further work.
- Download budget ~20 GB (owner decision 2026-11-02, D13): Balanced LLM (14 GB; Small 9 GB is the fallback under 32 GB RAM), TTS Q8_0 GGUF talkers CustomVoice + Base + tokenizer (4.4 GB), one whisper distil-large-v3 (1.5 GB). VoiceDesign and bigger LLM tiers on demand. `models_source` folder mode for offline installs.

## Next steps for a fresh orchestrator
1. `gh pr list` and `gh run list --branch main --limit 1`. Merge the pre-tag PR (`feat/release-0.1.1-pretag`) when CI is green (`gh pr merge --admin`), then wait for `main` CI to turn green.
2. Tag `v0.1.1`: confirm `VERSION`, `pyproject.toml` and `ns_common.__version__` say 0.1.1 and `CHANGELOG.md` has `## [0.1.1] - 2026-11-03` (`tests/test_release_wiring.py` checks both), then `git tag v0.1.1 && git push origin v0.1.1`. `release.yml` produces the GitHub Release with `Nightshift-0.1.1.zip`, its `.sha256` and `nightshift-app-0.1.1.zip`. `bins.qwentts` already points at the v0.1.0 asset, so `build-qwentts.yml` does not need to run again unless the binary changes (v0.1.0 is https://github.com/AbdulrahmanAmer/nightshift/releases/tag/v0.1.0).
3. First real run on the partner PC: send `Nightshift-0.1.1.zip` (Drive) with `OPERATOR.md`, run `INSTALL.cmd`, collect `verify-report.json`. The checklist is the "Verified on the partner PC" column of the open-gaps table in `docs/design/system-gaps.md` (kept in the orchestrator's worktree `D:\NightShift-main\docs\design\`; every row says *pending first run* and names what that run must confirm): time the voice stage of the first master (`logs\tts-*.jsonl` `tts_batch` rtf), check the interactive-only schedule line (NS-W205) and the 03:00 run, press Create it now once with the GPU idle, and look at `captions/report.json` `drift_ms` on the first real Shorts (the 120 ms gate may need to be raised if it sits near 100). Expect to fix what only a GPU shows (qwentts.cpp DLLs, TTS engine fallback `NS-W301`, WebView2 host fallback, the installer wizard's first run). Fill the column in after the first night.
4. Read BUILD_SPEC.md against the code for gaps that remain after the first run (series workshop production path, Assistant tool coverage, installer steps vs `ns` commands), file them as plan tasks, assign Sonnet builders.
