## Rules every plan follows

- **Nothing heavy on the build laptop.** No models, torch, llama.cpp, whisper. Heavy components are coded against their documented APIs and tested through fakes (spec §1.1). FFmpeg is the one real external tool used in tests.
- **Contracts freeze per slice** with a git tag `contracts-s<N>`. Later slices add; they change earlier contracts only via `contracts/CHANGE_REQUESTS.md`.
- **Worker model triage** (from `~/.claude/CLAUDE.md`): `sonnet` (effort high) for building and ordinary code tasks, `opus` for prompt design, policy logic and orchestrator design, `haiku` for mechanical sweeps. **Never run an agent on the Fable model**: no `fork` subagents, always an explicit `model`.
- **TDD per task**, commit per task, conventional commit prefixes (`feat:`, `test:`, `chore:`, `docs:`).
- **Clipper and Dashboard reuse the Slice 1 media code** (captions builder, renderer, QC, outbox) rather than duplicating it.
- **The dashboard UI must work offline (no CDN)** and is prototyped in `docs/superpowers/mockups/dashboard.html`, which the Slice 6 plan turns into `ns_dashboard/static/`.

**Slice 3 — Safety & growth** (WP-F, H, G).
